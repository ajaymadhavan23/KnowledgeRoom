# AGENT.md — Semantic Search with Embeddings

## Purpose of This Document

This is the instruction set for an AI coding assistant to implement semantic (meaning-based) search on the blog/notes app. Hand this file to the assistant as-is. It should locate the relevant project files itself rather than requiring pre-filled paths.

---

## Feature Summary

Add semantic search so users can find similar notes/blog posts by **meaning**, not just keyword matching. Example: searching "how to catch errors" should surface a post titled "exception handling techniques" even though they share no words.

Primary use case: when a user is about to **save or fork** a blog post, surface similar notes/posts they already have, so they can check for overlap before duplicating content.

### 2. Add an embedding generation service

Create a service (e.g. `embeddingService.js`) that calls Gemini's embedding model:

```javascript
const { GoogleGenerativeAI } = require("@google/generative-ai");
const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY);

async function generateEmbedding(text) {
  const model = genAI.getGenerativeModel({ model: "text-embedding-004" });
  const result = await model.embedContent(text);
  return result.embedding.values; // array of 768 floats
}

module.exports = { generateEmbedding };
```

Note: `GEMINI_API_KEY` should already exist in `.env` since the app already uses Gemini for the blog-writing agent — reuse it, don't create a duplicate key.

### 3. Update the BlogPost schema

Add an `embedding` field:

  type: [Number],

### 4. Generate the embedding on create AND update

Whenever a post is created or its content is edited, regenerate the embedding using a combination of its title + main text content (use whatever the actual content field is called — check the schema).

```javascript
const textForEmbedding = `${post.title}\n${post.content}`;
const embedding = await generateEmbedding(textForEmbedding);
```

Requirements:
- Do this **asynchronously relative to the response** where possible — don't make the user wait on the embedding call before their post saves. Save the post first, then update it with the embedding (fire-and-forget is acceptable, log errors, don't block the main request).
- Also needs to run for the **fork/copy** flow — when a user forks another user's post, the new copy should get its own embedding generated too (not copied from the original, since forking often changes content).

### 5. Write the similarity search query

```javascript
async function findSimilarPosts(postId) {
  const sourcePost = await BlogPost.findById(postId).select("+embedding");
  if (!sourcePost?.embedding?.length) return [];

  const results = await BlogPost.aggregate([
    {
      $vectorSearch: {
        index: "vector_index",
        path: "embedding",
        queryVector: sourcePost.embedding,
        numCandidates: 100,
        limit: 5,
      },
    },
    {
      $project: {
        title: 1,
        excerpt: 1,
        score: { $meta: "vectorSearchScore" },
      },
    },
  ]);

  return results.filter((r) => r._id.toString() !== postId);
}
```

Adjust the `$project` fields to match whatever display fields already exist on the schema (e.g. this app has `excerpt` per the existing schema — confirm and use real field names).

### 6. Expose an API endpoint

```javascript
// GET /api/blogposts/:id/similar
router.get("/blogposts/:id/similar", async (req, res) => {
  try {
    const similar = await findSimilarPosts(req.params.id);
    res.json(similar);
  } catch (err) {
    console.error("Similar posts lookup failed:", err.message);
    res.status(500).json({ error: "Could not fetch similar posts" });
  }
});
```

### 7. Backfill embeddings for existing posts

This can be a standalone script run once from the command line (e.g. `scripts/backfillEmbeddings.js`), not part of the regular app flow.
